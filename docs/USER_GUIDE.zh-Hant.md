# Zomate Fitness 使用手冊（繁體中文）

本文件說明 **Zomate PT 管理系統** 的主要功能與日常操作流程，適合管理員、櫃台人員與教練參考。

---

## 一、系統簡介

本系統用於健身中心管理：**學員入會與文件**、**課程／簽到**、**WhatsApp 付款通知與整合**，以及**財務與報表**。

| 區塊 | 說明 |
|------|------|
| 前端 | Next.js（App Router）、TypeScript |
| 後端 API | 正式連線至 FastAPI／PostgreSQL；本機依 `NEXT_PUBLIC_API_BASE_URL` 連線，只有啟用 Next mock API 設定時才使用模擬路由 |
| 詳細技術與路線圖 | 請參考總庫或內部的 `docs/REQUIREMENTS.md`；模擬 API 行為見 `docs/MOCK_API_SIMULATION.md`（若本倉庫未附完整檔案，請向開發團隊索取） |

---

## 二、後台登入

1. 開啟瀏覽器，進入應用程式的 **登入頁**（路徑：`/login`）。
2. 輸入帳號、密碼後送出。
3. 登入成功後會進入後台（預設導向 `/admin`）。

**內建種子帳號（開發／本機環境）：**

- **管理員（ADMIN）**：`masterzoe` / `12345678`
- **櫃台（CLERK）**：`worker` / `12347890`

登入狀態會儲存在瀏覽器的 **localStorage**。若需換帳號，請先登出再重新登入。

## 三、後台介面導覽

登入後會進入共用後台版型（左側選單＋頂欄）。側欄會定期檢查 **API 連線**；若使用本機模擬 API，資料庫健康檢查可能顯示為不適用（NA）。

### 3.1 Dashboard（後台面板）

- **後台面板**（`/admin`）：總覽與快捷入口。

### 3.2 學員管理（Student Management）

- **學生名單**（`/admin/students`）：檢視與管理學員資料。
- **入職紀錄／健康表單**（`/admin/onboarding-records`）：與入會、PAR-Q 等表單紀錄相關之查閱與管理。

### 3.3 課程與出勤（Course & Attendance）

- **教練上堂**（`/coach`；教練端 `/coach-portal`）：職員／教練管理跟進學員上堂日程；可篩選課程類型。
- **學生上堂**（`/coach/calendar`；教練端 `/coach-portal/calendar`）：月曆與簽到相關畫面。
- **教練出勤**（`/coach/attendance`；教練端 `/coach-portal/report`）：月份下拉（`yyyy-MM`，預設本月）；表格 Course Type｜Students｜上堂日期；可匯出 Excel。
- **QR 簽到中心**（`/admin/attendance/qr-console`）：管理／產出 QR 簽到相關流程之控制台。
- **Session Ledger · 扣堂原因**（`/admin/attendance/session-ledger`）：節數／堂數帳本；可記錄理由類型（例如：實際出席、遲到取消、教練補堂等）。報表支援匯出 Excel。
- **試堂／開課管理**（`/student/trial`）：試聽課程相關管理（與完整後端整合狀態請以專案 `REQUIREMENTS.md` 為準）。
- **學生入口**（`/student`）：學員面向之入口頁連結。

### 3.4 財務與行政（Finance & Admin）

- **銷售與分期**（`/admin/finance/sales`）：月銷售報表、分期欄位等；可匯出 Excel／CSV（與畫面表格一致）。側欄財務區僅保留此項。
- **支出管理**、**薪酬／出勤報表**：已自管理報表排除（教練自行記出勤）；舊路徑 `/admin/finance/expenses`、`/admin/finance/payroll` 會重新導向至銷售頁。
- 側欄已不再提供「財務總覽」入口；若開啟 **`/admin/finance`**，會自動 **重新導向** 至 **`/admin/finance/sales`**。

### 3.5 系統設定（System Settings）

- **Whatsapp 設定**（`/admin/settings/whatsapp`）：連線欄位、**template 訊息草稿**，以及 **已發送訊息** 列表（`GET /api/admin/whatsapp-logs`）。舊路徑 **`/admin/whatsapp`** 會導向此頁。

## 四、學員端常用流程

以下為學員或現場使用之公開／半公開路徑（無需後台帳號即可完成部分步驟，實際依部署設定為準）。

### 4.1 新學員入會與文件（Onboarding）

- 路徑：**`/student/onboard`**
- 依精靈步驟填寫：姓名、電話、電郵、**香港身份證（HKID）** 等。
- **PAR-Q** 七題為是／否；若有任一是「是」，需配合 **醫療 clearance**（系統會要求記錄／上傳相關資訊，詳見畫面）。
- 可區分**新入會**與**續會**，並可填寫備註。
- 政策提示：系統會帶出會籍效期邏輯（例如 **10 堂對應 3 個月**、**30 堂對應 6 個月**）與 **7 天冷靜期** 確認（以畫面與後端實作為準）。

### 4.2 QR 簽到（Check-in）

- 路徑：**`/student/checkin`**
- 可使用 **掃描 QR** 或 **貼上 QR 內容** 完成簽到。
- 另有 **PIN** 驗證及選填 **電話** 後備流程。
- 實務上可能僅允許 **當日** 簽到（依專案需求與實作）。

### 4.3 學員首頁

- 路徑：**`/student`**  
  作為學員功能入口或指引頁。

## 五、四大核心業務（概念摘要）

1. **數碼化行政入職**：學生填表與免責／健康聲明 → 後台可即時查閱紀錄。  
2. **試堂與購買**：試堂註冊、收款確認後，可透過 WhatsApp 等管道通知餘額（依實際整合為準）。  
3. **智能 QR 簽到**：掃碼與 PIN → 扣堂與相關通知（依實際整合為準）。  
4. **管理後台財務**：入機、分類統計、月報與 Excel 匯出。

## 六、通知與整合（參考）

### [F005][S003] 正式 WhatsApp 付款通知（2026-10-13）

系統通知號碼為 **9756 8105**；人手查詢為 **6052 9291**。四款 `zh_HK` / `UTILITY` Meta 範本均已批准並接駁正式後端；四款後端測試已真實發送到指定測試電話，使用者確認全部收到。測試使用合成課程、PIN、堂數及金額，沒有建立真實付款；`dry_run: false` 只代表實際呼叫發送 API，並不代表內容是真實業務資料。

| 通知 | 實際選用條件 | 收件人 |
| --- | --- | --- |
| 付款／收據待確認 `zomate_payment_pending` | 付款／續會提交時沒有附收據，或職員手動催款指定「收據未確認」 | 學生 |
| 分期付款 `zomate_payment_installment` | 有收據，且後端識別為分期；例如上傳對應分期收據並開啟 WhatsApp 通知 | 學生 |
| 全數付款 `zomate_payment_full` | 有收據，且後端沒有識別為分期；一次付清個案須核對後端付款／分期判定 | 學生 |
| 教練開課／付款 `zomate_payment_coach` | 上述付款通知操作同時指定通知教練，並能找到對應課程教練及電話 | 該課程教練 |

**職員操作：**到 [學生名單](https://zomate-fitness-system-front.vercel.app/admin/students)，開啟學生詳情，上傳收據時選好對應 Course／分期，勾選「上傳後產生 WhatsApp 提醒（學生）」；要教練收到，另勾「同時通知教練」。兩項預設勾選；取消學生通知會停止這次學生及教練付款通知。教練入口上傳收據只通知學生，不會另發教練版本。學生已拒絕 WhatsApp 通知時，正常學生通知會跳過。

付款／報 Course 提交會經 `POST /api/renewals` 觸發；上傳收據會經會員／職員／教練 receipt API 觸發。後台開課成功畫面的分期 reminder 按鈕會使用「待確認」版本，並可同時通知教練。這四款不會因每日到點或每次簽到自動發出；分期備註內的「第幾堂付款」目前是訊息內容，不是自動排程。

**目前流程限制：**收據上傳在程式中直接視為 `receipt_confirmed=true`，沒有另等財務人手核准；全數付款範本的選擇也不是獨立核實銀行已全額到帳。「報 Course」精靈先寫入付款、再建立新課程，因此首次付款通知可能沒有新課程 PIN，或仍取學生最近的舊課程／分期狀態。四款發送測試通過不等於此報名流程已完成驗收；正式使用前需核對課程關聯、PIN、分期、課程總額及尚欠金額。

**動態資料：**課程名稱來自對應課程紀錄（`course_title`），Meta 使用 `{{1}}`，後台預覽使用 `{{course_title}}`；「測試課程（測試資料，並非實際付款）」只存在於測試呼叫參數，不是正式模板固定字眼。`next_lesson_date` 現時為課程開始日期，並非下一堂實際時間；`amount_paid` 顯示付款記錄金額，未必是累計已付金額。不要在後台改字後假設 Meta 核准範本也同步更改；Meta 固定文案修改需要另行提交審批。

[WhatsApp 設定](https://zomate-fitness-system-front.vercel.app/admin/settings/whatsapp) 可核對已啟用、憑證及映射。其「已發送訊息」列表是應用程式紀錄，不能單靠此列表當作手機送達證明；專用測試 API 不會新增此列表紀錄。

**測試權限：**`POST /api/admin/whatsapp/test-send` 只限 username `masterzoe`，且角色為 `ADMIN` 或 `MASTER_ADMIN`。其他登入者 403、未登入者 401。此限制只適用測試入口；正常付款／收據操作仍按原有職員權限執行。

- Meta 已批准並設定映射的付款／簽到通知會真實發送；未有映射的其他通知及本機 mock 環境可能只記錄／提供手動 WhatsApp 連結。
- 側欄 **API／DB 狀態** 可用於快速判斷前後端是否連線正常。

### [F003][S003] 學生上堂簽到通知

學生成功 QR／PIN 簽到，或現有 Face ID 簽到路徑成功處理後，後端先保存出勤並扣 1 堂，再用 **9756 8105** 發送：

| 對象 | Meta 範本 | 動態資料 |
| --- | --- | --- |
| 學生 | `zomate_checkin_student` | 學生姓名、課程名稱、香港簽到時間、扣堂後帳戶剩餘總堂數 |
| 該課程教練 | `zomate_checkin_coach` | 學生姓名及電話、課程名稱、香港簽到時間、學生扣堂後帳戶剩餘總堂數 |

資料庫電話按香港 **+852** 處理：八位本地號碼會補 `852`，已有 `+852`／`852` 的號碼不會重複加國碼。訊息的姓名、課程、時間及堂數均由本次簽到資料取得，沒有寫死測試字眼。

相同學生／課程／香港同日重複簽到會被拒絕，不再次扣堂或發通知（一般為 409；餘額不足亦可能先回覆 400）。簽到寫入失敗亦不發成功通知。學生未同意 WhatsApp 通知時跳過學生版本；沒有可用教練電話時跳過教練版本。顯示的堂數是學生帳戶總餘額，不是該課程餘額。現有 Face ID 接口仍屬模擬識別入口；這次接上通知不代表真實 Face ID 裝置已部署。職員手動扣堂不屬這兩款成功簽到通知。

前面四款付款訊息與這兩款簽到訊息分開，合共 **6 款業務範本**，另保留原有預約確認。測試發送入口仍只限 masterzoe。

## 七、疑難排解（簡要）

| 狀況 | 建議 |
|------|------|
| 無法登入後台 | 確認帳密、清除本網站資料後重試，或確認後端／模擬 API 是否啟動。 |
| 資料與預期不符 | 若未設定 `NEXT_PUBLIC_API_BASE_URL`，目前可能為**記憶體模擬資料**；正式環境請連線真實 API。 |
| 匯出 Excel 異常 | 確認瀏覽器未阻擋下載，並確認該頁資料已載入完成。 |
